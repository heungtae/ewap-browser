## 2. 읽기 경로

Claude의 `read_page`는 Chrome Accessibility API가 아니라 content script가 DOM을 순회해 만든 접근성 유사 트리다.

- tag와 `role`을 button, link, textbox, combobox, heading 등으로 매핑한다.
- accessible name 후보로 `aria-label`, placeholder, title, alt, label text, input value와 직접 text node를 사용한다.
- 각 element에 `ref_N`을 부여하고 `WeakRef`로 element를 기억한다.
- 기본 depth는 15, element 상한은 10,000, 기본 출력 상한은 50,000자다.
- `filter=all`은 visibility와 `aria-hidden` 검사를 건너뛰므로 hidden DOM도 기본 결과에 들어갈 수 있다.
- password, hidden input과 일부 autocomplete 값은 `[value redacted]`로 바꾸지만 일반 input의 짧은 현재 값, href, placeholder와 option value는 포함될 수 있다.
- `ref_id`를 다시 전달하면 해당 element subtree만 읽는다.

추가 읽기 도구는 다음과 같다.

| 도구                    | 관찰된 역할                                                              |
| ----------------------- | ------------------------------------------------------------------------ |
| `get_page_text`         | article/main 계열 selector 중 가장 긴 `innerText`를 우선 추출            |
| `find`                  | 전체 page tree와 자연어 query를 작은 모델에 보내 최대 20개 ref 후보 반환 |
| `computer.screenshot`   | CDP `Page.captureScreenshot` 결과를 모델 tool result로 반환              |
| `computer.zoom`         | viewport 일부를 capture/crop/resize해 모델에 반환                        |
| `tabs_context`          | 관리 중인 tab group의 tab ID, title, URL 반환                            |
| `read_console_messages` | `Runtime.enable` 이후 console event 수집                                 |
| `read_network_requests` | `Network.enable` 이후 request URL, method, status 수집                   |

## 3. 제어 경로

Claude는 ref 기반 DOM 경로와 좌표 기반 CDP 경로를 함께 사용한다.

1. `computer`가 ref를 받으면 content script가 element를 `scrollIntoView`하고 bounding box 중앙을 계산한다.
2. 좌표가 직접 들어오면 screenshot scale context를 viewport 좌표로 환산한다.
3. CDP `Input.dispatchMouseEvent`, `Input.dispatchKeyEvent`, `Input.insertText`로 trusted input을 보낸다.
4. scroll은 CDP wheel이 효과가 없으면 content script `scrollBy`로 fallback한다.
5. `form_input`은 DOM property를 직접 변경하고 `input`/`change` event를 보낸다.
6. `navigate`는 `chrome.tabs.update`, history API와 beforeunload dialog handler를 사용한다.
7. `javascript_tool`은 CDP `Runtime.evaluate`로 임의 page-context JavaScript를 실행한다.
8. `browser_batch`는 여러 도구를 순차 실행하고 첫 오류에서 중단한다.

도구군에는 click, right/double/triple click, type, key, scroll, drag, hover, screenshot, zoom, navigate, form input, tab create/close, image/file upload, console/network read, arbitrary JavaScript와 GIF/shortcut 기능이 포함된다.

## 4. 권한과 lifecycle

- 권한 종류는 navigation, page read, console/network read, click, type, upload, JavaScript, domain transition 등으로 나뉜다.
- host별 once/always allow와 always deny를 저장한다.
- `follow_a_plan`은 사용자가 승인한 domain 집합으로 현재 turn을 제한한다.
- `skip_all_permission_checks`는 일반 host/tool permission prompt를 생략한다.
- 별도 category service가 위험·조직 차단 사이트를 거부한다.
- debugger는 tool 실행 전에 attach하며 active tool이 없어진 뒤 약 20초 후 detach한다.
- CDP command가 detached 오류를 반환하면 debugger를 다시 attach하고 command를 한 번 다시 실행한다.

## 6. 채택 판단

규범 설계는 다음을 채택한다.

- depth/ref/max-char를 갖는 `read_page`
- 본문 중심 `get_page_text`
- deterministic-first `find`
- screenshot/zoom vision fallback
- 승인된 tab group context
- read-only batch
- tool timeline, screenshot annotation, permission/action modal, plan card와 복구 가능한 streaming Chat UI
- `standard`, `follow_a_plan`, `skip_all_permission_checks` permission mode
- `read_page`와 초기 page projection에서 hidden DOM을 기본 포함하는 `all_dom` scope

다음은 채택하지 않는다.

- 출처와 license가 확인되지 않은 minified code의 직접 복사
- model이 임의 좌표·selector·CDP method를 지정하는 계약
- `Runtime.evaluate`와 임의 JavaScript tool
- password, OTP, recovery code와 token target 자동 입력
- dispatch 이후 fallback 또는 자동 retry
- command 성공만으로 결과적 행동을 `VERIFIED` 처리하는 방식
