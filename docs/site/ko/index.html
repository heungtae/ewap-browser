ContextPilot 설치

Chrome 116 이상이 필요합니다. 소스에서 빌드하려면 Node.js 20 이상과 pnpm@9.15.4를 준비하세요. 복제한 저장소의 루트에서 다음 명령을 실행합니다. 

corepack enable
pnpm install --frozen-lockfile
pnpm exec tsc -p tsconfig.build.json
node scripts/build-extension.mjs
pnpm validate:package
  1. chrome://extensions에서 개발자 모드를 켭니다.
  2. 압축해제된 확장 프로그램을 로드합니다를 누르고 저장소의 dist-extension/을 선택합니다.
  3. 확장 프로그램 옵션 페이지(Settings)에서 모델 Provider를 설정합니다.
  4. 작업할 웹 페이지를 열고 ContextPilot 사이드 패널을 엽니다.

로컬 ZIP이 필요하면 빌드 후 pnpm package:local을 실행하세요. dist/contextpilot-<version>.zip을 압축 해제하고 해당 폴더를 로드합니다. Chrome Web Store 설치가 아닌 압축 해제 설치 방식입니다.

위 명령은 확장 버전을 유지합니다. pnpm build와 pnpm test는 버전을 증가시킵니다.

모델 Provider 연결

  1. Settings → LLM Provider에서 Provider ID를 입력하고 해당 Plugin을 선택합니다.
  2. Provider의 Endpoint와 Model을 입력합니다. 지원하는 Wire API(자동, Chat Completions, Responses)를 선택합니다.
  3. 인증 방식을 선택하고 필요한 경우 secret 필드에 API key를 입력합니다. Provider가 요구할 때만 HTTP header를 추가합니다.
  4. 설정을 저장한 뒤 연결 테스트를 실행합니다. Provider 관리에서 사용할 Provider를 활성화합니다.

HTTP endpoint는 HTTP host 권한을 요청해야 합니다. 사설 IPv4 endpoint는 사설망 사용 동의도 필요합니다. Endpoint·모델·인증 형식은 해당 Provider의 API 문서를 확인하세요.

설정은 현재 Chrome 프로필에 저장됩니다. 요청에 대해 승인한 페이지 문맥은 선택한 Provider로 전송될 수 있습니다. 확장이 로컬에서 동작하더라도 원격 모델까지 로컬에서 실행되는 것은 아닙니다.

페이지에 질문하기

  1. 질문할 페이지와 ContextPilot 사이드 패널을 엽니다.
  2. Ask를 선택하고 “이 페이지를 요약하고 핵심 내용을 정리해줘”처럼 질문합니다.
  3. 페이지·소스·화면 접근 요청이 나타나면 내용을 확인한 뒤 동의합니다.
  4. 답변을 읽고 같은 대화에서 추가로 질문합니다. 중요한 결론은 원문과 비교하세요.

표나 목록에는 “화면에 보이는 표를 읽고 값을 비교해줘”처럼 요청해 보세요. 읽을 수 있는 데이터는 페이지·접근 권한·지원 도구에 따라 달라집니다. 소스를 선택해야 할 때는 페이지 데이터 읽기 기능을 사용하세요.

브라우저 작업 실행

  1. 작업을 시작할 페이지에서 Act를 선택합니다.
  2. “검색창에 ContextPilot을 입력하고 결과를 보여줘”처럼 목표와 정확한 값을 설명합니다.
  3. 사이드 패널에 나타나는 계획·동작 검토 안내를 따릅니다. 승인하기 전에 목적지와 입력값을 확인하세요.
  4. 실행 상세와 실제 페이지 변화를 확인합니다. 진행 중인 요청은 Stop으로 취소할 수 있습니다.

페이지가 바뀌거나 대상을 식별할 수 없으면 새 관찰·선택 안내를 따릅니다. 작업이 차단되거나 미완료로 끝날 수 있으므로 최종 상태와 실제 페이지를 함께 확인하세요.

권한과 개인정보

Settings의 승인 설정을 확인하고 의도한 작업에 필요한 접근을 허용하세요. 페이지 접근, 소스·vision 공유, 중요한 동작은 실제 UI의 안내를 따릅니다. 저장된 권한은 Settings에서 철회하고 새 요청으로 적용 결과를 확인할 수 있습니다.

API key는 secret 필드에 저장하세요. 공유용 설정이나 문의 자료에 key·인증 header·민감한 페이지 원문을 넣지 마세요. 진단을 내보낼 때도 공유할 자료를 확인하세요.

조직에서 관리하는 확장이라면 필요한 서비스나 정책 제한은 관리자에게 문의하세요.

업데이트와 복구

  1. Chrome을 종료하고 현재 확장 폴더를 백업합니다.
  2. 같은 경로의 내용을 새 ZIP의 압축 해제 내용으로 교체합니다.
  3. Chrome을 다시 열고 확장 버전·Settings·Provider 연결·권한을 확인합니다.
  4. 복구하려면 Chrome을 종료하고 같은 경로에 이전 패키지를 복원합니다.

설치 경로를 바꾸면 확장 ID와 저장소가 달라질 수 있습니다. 대화는 브라우저 세션 저장소를 사용하므로 Chrome 재시작 후 보존을 전제로 하지 마세요. 업데이트 전에 버전과 설치 경로를 기록하세요.

문제 해결

확장이 로드되지 않아요
Chrome 116 이상인지 확인하고 빌드된 manifest.json이 들어 있는 폴더를 선택하세요. 저장소 루트나 ZIP 파일 자체를 선택하면 안 됩니다.
Provider 연결이 실패해요
Plugin·endpoint·wire API·모델·인증·host 권한을 확인하세요. 변경 사항을 저장한 뒤 연결 테스트를 다시 실행합니다.
페이지 데이터나 동작을 사용할 수 없어요
현재 탭과 접근 요청을 확인하세요. 실행 상세에서 권한 거부·오래된 페이지·지원하지 않는 대상·Provider 오류를 확인하고 필요한 경우 새 요청을 시작합니다.
문제를 제보하고 싶어요
확장 버전·Chrome/OS·재현 단계·기대 결과·실제 결과를 기록하세요. 화면과 진단 자료에서 민감한 값을 제거합니다.
