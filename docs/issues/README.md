## 작업 절차

1. 수정 전 목록에서 관련 이슈와 회귀 조건을 확인한다. 같은 원인의 재발은 기존
   ID를 유지하고 발생 이력을 추가한다. 다른 원인이면 새 ID를 부여하고 서로 연결한다.
2. 새 기록은 [양식](issue-template.md)을 복사해 `records/YYYY-MM-DD-short-name.md`에
   작성한다. ID는 `ISS-YYYYMMDD-NNN`을 사용하고 목록 행을 같은 변경에서 추가한다.
3. 원인, 기존 동작을 보존해야 하는 경계, 해결안과 검증 범위를 기록한 뒤 상태를
   `해결안 정리` 또는 `수정 중`으로 갱신한다. 추정과 확인된 사실을 구분한다.
4. 수정에는 해당 증상을 재현하는 회귀 테스트를 포함한다. 영향받는 이전 이슈의
   회귀 조건도 확인하고 실행 명령·결과·revision·환경을 기록한다.
5. 소스 테스트, 통제 Chrome, 실제 사이트·Provider, 배포 확인의 결과를 각각
   기록한다. 필요한 runtime 확인이 남으면 `검증 중`으로 유지한다.
6. 완료 조건을 충족하면 수정 commit, 회귀 테스트 경로와 실행 증거를 연결하고
   `해결`로 변경한다. 배포 버전은 실제 확인된 경우에만 기록한다.
7. 재발하면 기존 해결 이력을 보존하고 새 환경·진단·차이·원인을 추가한다. 해당
   범위의 상태를 `재발`로 되돌린다. 이전 PASS를 새 검증 결과로 재사용하지 않는다.

각 단계에서 상세 기록과 목록의 상태·최근 갱신·다음 작업을 함께 갱신한다. 회귀
테스트 경로는 상세 기록에서 관리하고, 실행 증거는 [evidence](../evidence/README.md)에
연결한다. 해결된 기록과 회귀 테스트는 후속 변경에서도 유지한다.

## 기록할 증거

- 발생 버전, source revision 확인 여부, 요청 ID, 시각과 재현 조건.
- 관찰된 stage·outcome·reason과 관련 코드·테스트 경로.
- 수정 commit, 실행한 검증 명령·결과·환경, 미검증 범위, 완료 조건 충족 여부.
- 재발 시 이전 해결 기록과 이번 발생을 연결하는 날짜별 이력.

진단 원본 ZIP은 저장소에 넣지 않는다. 자격증명, 입력값, page/provider 원문과
민감한 URL을 기록에 복사하지 않고 안전한 코드·통계·상태와 증거 식별자를 사용한다.
