# ISS-20261031-006: Live sender check rejected Chrome side panel

Status: **검증 중**. Discovered 2026-10-31 while testing S28 live sender validation added in `5073ee3e0`. Actual Chrome for Testing 147 on Linux returned `windowId: -1` for a real `SIDE_PANEL` context and omitted `documentId` in its runtime message sender. The initial check required both and rejected bridge requests. The earlier positive test opened the panel HTML as a tab and therefore did not cover this case.

For an identified document, the check requires exact extension ID, URL and unique live context; an extension tab requires a nonnegative window. For a sender without `documentId`, a separate fallback permits only `capabilities` and `resumeEvents` when its origin and URL match and there is exactly one live side-panel context. Responses on this fallback are strictly limited to readiness and browser connection events: task content, approvals and migration commands are denied. This is not proof of sender document or window ownership, and multiple side panels fail closed.

In the first actual Chrome attempt, allowing the `-1` window sentinel alone still returned `BACKEND_UNAVAILABLE`; inspection showed the missing sender `documentId`. The restricted fallback then passed in [Chrome for Testing 147/Linux](../../evidence/s28-real-sidepanel-2026-10-31.json): an actual opened side panel received capabilities and connection replay, while a migration request was denied. The test uses an isolated profile and synthetic click; it does not prove multi-window ownership, stale-context isolation or a real task flow. S28 unit, type and boundary checks are recorded with the Sprint evidence.

`pnpm test:s28` passed 46 tests, including negative tests for foreign origin, duplicate side panels, unbound migration and task-bearing bootstrap responses. `pnpm build:s28`, `pnpm check:s28`, typecheck, ESLint and script formatting passed. The first boundary check rejected the enlarged test module; moving the sender tests into the bounded bootstrap module corrected it. No provider calls, approvals or business dispatches occurred. The migration negative in the Chrome fixture also uses an incomplete migration command, so it does not alone prove the sender guard rejected a valid migration command; that boundary is checked by the unit tests.
