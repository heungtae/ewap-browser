## 구현 보정

- Settings mode 저장 전후로 모든 열린 tab의 활성 run/request를 취소하고
  CDP를 중단하며 pending permission과 plan scope를 지운다. 저장 중
  시작한 요청도 저장 후 취소한다. Panel-origin 설정 변경은 거부한다.
- `PLAN_APPROVE`는 live Act session의 현재 exact origin 한 개만
  `follow_a_plan` mode에서 수락한다. 종료된 session의 plan scope를
  제거하고, 승인하지 않은 다음 요청은 `PLAN_SCOPE_VIOLATION`으로 닫는다.
- 계획 origin은 URL 사용자 정보·query·fragment를 거부한다. IDN은 URL
  punycode 정규화를 사용하고 subdomain·port·trailing dot은 다른 origin으로
  취급한다. 위반 오류는 Side Panel에서도 구분해 보여 준다.

Settings에서 skip mode를 확인 문구 없이 저장하려면 실패했고, 정확한
문구를 입력한 뒤 저장됐다. Side Panel이 직접 보낸 설정 변경 요청은
거부됐다. 새 skip run은 mode badge를 표시하고 permission card 없이
trusted R1 click을 실행했다. R2 invoice는 permission card 없이도 추가
confirmation card가 나타났고, 확인 전 페이지 변화가 없었다. 두 실행은
postcondition 확인과 debugger detach로 종료됐다.

skip을 해제한 standard run에서는 permission card가 다시 나타났다.
사용자가 저장한 deny 뒤 skip을 재활성화해도 클릭과 새 permission card가
없었다. follow-plan run에서는 현재 도메인 계획 승인 후 R2 확인을 거쳐
실행했고, 임의 session ID의 계획 승인은 거부됐다. 완료된 계획은 다음
Act 요청에 적용되지 않아 실행 전 실패했다. Provider 요청에는 fixture
password 원문이 없었다.

## 18번 permission matrix 대응

| 범위 | 이번 로컬 증거 |
| --- | --- |
| standard/follow-plan/skip | Chrome standard prompt 복귀, exact-origin plan 승인, skip permission card 0과 R1/R2 성공. S2 Chrome의 once/always/deny/revoke 회귀 |
| PERM-SKIP-001~005 | Panel save 거부, Settings typed phrase, mode badge, 취소-저장-취소 unit, skip R1 및 standard 복귀 Chrome |
| PERM-SKIP-006~010 | unit exact origin/IDN/port, stored deny Chrome, skip R2 추가 확인 Chrome, 기존 S2 CDP/restricted/credential 경계와 R3 policy unit |
| PERM-SKIP-012 | standard 복귀 후 grant 없는 permission 재요청과 저장된 deny의 skip 유지 Chrome |
| follow-plan | live session/current origin만 승인하는 unit, 잘못된 session 및 다음 요청 plan 재사용 거부 Chrome |

PERM-SKIP-011 managed disable은 S12의 managed 정책 계약이 필요하다.
PERM-SKIP-013의 durable mode-change audit/export는 S13 범위다. 이번
Browser 검증은 Provider의 credential 원문 부재와 기존 진단 allowlist
회귀까지 판정한다. cross-domain redirect의 실제 Chrome 시나리오,
모든 tool/host/risk 조합의 운영 사이트 실험 및 실제 enterprise PDP는
이번 로컬 종료의 증거가 아니다. mode 변경의 다중 tab 취소는 코드와
설정 handler 단위 순서 테스트로 확인했고 실제 Chrome 동시 tab 취소는
별도 회귀 항목으로 남는다.
