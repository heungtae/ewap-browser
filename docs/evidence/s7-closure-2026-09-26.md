## 구현 보정

- 서명된 Profile에 action 정의가 있으면 그 정의만 모델의 일반 Act 도구로
  내보내고, workflow 단계도 동일한 Profile 정의에 결합한다. R2가 페이지
  기본 R1로 낮아지는 경로를 제거했다.
- Resolver 설정 부재만 page-derived action fallback으로 처리한다. 설정된
  Resolver의 서명·claim·조회 실패는 `PROFILE_UNAVAILABLE`로 닫는다.
- 일반 Act chat의 R2 confirmation token을 현재 대화 session ID에
  결합했다. 수정 전에는 권한 승인 뒤 `CONFIRMATION_INVALID`로 종료됐다.
- page-derived click에 확인 가능한 postcondition이 없으면 CDP dispatch
  전에 `FAILED`로 닫는다. 임의의 페이지 변경을 성공으로 추정하지 않는다.

Chrome S7의 각 정상 사례에서 classifier는 action tool 없이 1회 호출됐고,
두 번째 Provider turn에서 허용된 proposal 도구만 노출됐다. 사용자 검토와
permission 전에 페이지 변화가 없었다. invoice는 R2 확인 카드 전에
변화가 없었고, 확인 뒤 `isTrusted` click으로 버튼이 disabled가 됐으며
semantic postcondition이 확인됐다. case도 `isTrusted` click과 disabled
결과를 확인했다. note는 사용자가 Side Panel 값 카드에 `Reviewed note`를
입력한 뒤 `isTrusted` beforeinput과 값 교체를 확인했다. 정상 사례는
각각 결과를 Provider에 전달해 최종 답변을 표시했고 debugger가 detached
상태로 끝났다. Provider 요청에는 password fixture 값이 없었고, note의
사용자 입력값은 Provider 요청과 Chrome local/session storage에 없었다.

손상 JWS 사례는 classifier 이후 Provider action planning을 호출하지
않았고 클릭·debugger attach가 없었다. postcondition 없는 page-derived
click은 검토·permission 이후에도 페이지 변화와 debugger attach 없이
실패했다. 두 사례 모두 실패 card와 terminal UI를 확인했다.
