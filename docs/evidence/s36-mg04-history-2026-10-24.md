## Actual source and behavior

- [History converter](../../apps/chrome-extension/src/migration/mg04-convert.ts) reads only `chat_session_v1`, whose actual legacy owner is `chrome.storage.session`. It accepts absent/null cleared sessions, validates v1 containers and each original event with the existing chat validator, checks matching session/thread/tab ownership and increasing event sequences, and quarantines invalid/duplicate threads. Limits match the legacy eight threads, 128 KiB event history per thread and 1 MiB session snapshot. Invalid containers are counted as one quarantined container; valid containers count threads. Originals remain in a browser-local snapshot.
- [History event projection](../../apps/chrome-extension/src/migration/mg04-events.ts) emits an archive format with `legacyType`, `legacyRunId`, sequence and display metadata. It is not a `ChatEvent` stream. User/assistant text, tool summaries, status/completion and historical approval decisions remain visible as history. Pending confirmation/action/value/permission/source requests become informational markers without action objects, proposed values, IDs/nonces or grants. A verified action with an unknown goal stays that way. Missing terminal events do not manufacture completion or create a resumable task.
- Records retain legacy session/thread IDs and historical tab/scope context; `historyOnly: true`, `executable: false` and `reconnectAllowed: false` are explicit. Historical tab IDs/epochs are not current browser bindings. The source schema has no window ID; this converter does not invent window ownership or qualify actual UI/window restoration.
- [MG04 staging](../../apps/chrome-extension/src/migration/mg04-staging.ts) uses a session-storage/freeze port and the [common local staging implementation](../../apps/chrome-extension/src/migration/local-staging.ts). It atomically stores original snapshot, conversion, quarantine and checkpoint in the existing profile-specific IndexedDB migration journal under an MG04 namespace. It does not write Chrome session storage, create graph datasets, invoke legacy chat restore or feed a live event channel.

MG03 now delegates to the common staging implementation with its original source keys, schema, namespace and error codes. Readback additionally checks migration ID, stored key and epoch as well as snapshot/conversion digests. MG03 and MG04 can use the same migration ID without colliding. Previously recorded MG03 evidence is preserved; the regression uses a separate dated output directory. Chrome runners default to ignored `dist/s36/` output and accept explicit evidence-directory environment variables for a dated run.

The production storage/freeze/writer integration is still absent. `FrozenSource.assertFrozen` is a trusted runtime composition port, not a caller-supplied claim. All source writers must stay frozen; digest rereads do not create a cross-store transaction. Source snapshots may contain private local history and old authority payloads as non-executable recovery data; no snapshot is printed, transmitted to a backend/model, or exposed through a query/tool route. Retention/access/cleanup integration remains pending.
