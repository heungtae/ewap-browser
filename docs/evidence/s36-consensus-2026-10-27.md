## Implemented scope

- [Strict contracts](../../packages/shared/src/migration-rpc.ts) add optional
  `migration.consensus.validate/acknowledge`. The native bridge advertises
  `migration.consensus` only with an explicitly composed settings store. Both
  privileged endpoints apply the existing bounded settings-source parser and
  192 KiB limit. Browser ACKs must name the extension owner; providers and content
  scripts do not gain a management path.
- The [browser client](../../apps/chrome-extension/src/migration/consensus-rpc.ts)
  checks the pinned manifest, all six current sources, five browser staging stores,
  MG01 credential readback and freeze before and after the response. Validation
  advances `copying` to `validated` without an owner ACK. Acknowledgment persists
  and verifies the browser owner's actual IndexedDB ACK before sending it, and
  verifies it again afterward. Validation replies cannot introduce owner ACKs;
  acknowledgment replies must contain matching extension/backend digests.
- The [backend](../../apps/agent-server/src/migration/consensus-rpc.ts) binds
  profile, migration ID, epoch, revision, source digests and manifest/checkpoint
  digest to the retained journal. It independently reads typed MG01 staging,
  actual credentials through the explicitly selected store, and the MG02 mirror.
  It rechecks the request context, journal/fence and mirror after asynchronous
  credential readback. Only then can it advance validation or atomically record
  matching extension/backend ACK digests. Exact duplicate requests do not advance
  revision again. It does not copy settings secrets or activate provider roles.
- Raw MG01 source is request-scoped, using the existing authenticated settings
  validation path. It is never persisted in the journal or returned. MG03–MG06
  target validation belongs to the current authenticated browser owner; the backend
  does not independently read IndexedDB. Actual writer freeze is still a controlled
  fixture assertion, not an installed source-writer implementation.

## Remaining acceptance

readiness after source/target/credential changes. Any failure after a durable reply
can leave historical metadata; commit must perform fresh complete readback and
ownership checks. No remote commit/prepare/fence/activation/rollback API was added.
Actual source/target writer freeze/drain/restart ownership, explicit session-source
recovery, installed commit composition, browser-process-restart and OS-store
qualification of this endpoint, full UI/live JEV/holdout gates, supported normal-user
deployment and release delivery remain open. Original architecture/Sprint designs,
production routing, UI and version are preserved; S36 stays In Progress and S37
