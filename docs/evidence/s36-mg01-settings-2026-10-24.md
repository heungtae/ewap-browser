## Implemented source path

- [Source decoder](../../apps/agent-server/src/migration/mg01-source.ts) reads only the trusted owner's `provider_settings`, preserves exact absent/null/empty source digests and accepts bounded v1/v2 records. Source limit is 4 MiB, 64 providers and 64 custom headers per provider. Malformed/unsupported data remains in the original source; only indexed reason summaries are staged. An invalid container counts as one disposition, while a valid container counts each provider.
- [Converter](../../apps/agent-server/src/migration/mg01-convert.ts) keeps public provider IDs, names, endpoint/model/auth metadata, header names, timeouts and historical enabled/private-network flags. It reuses the original full provider config/header validator after credential merging, then the S34 role-candidate logic. Disabled and non-GPT records remain disabled/repairable; invalid providers do not poison valid siblings. Source HTTP endpoints unsupported by target credential identity remain in the original namespace for repair. Public metadata containing any known API/header credential value is quarantined before transfer/persistence.
- [Credential transfer](../../apps/agent-server/src/migration/mg01-credentials.ts) uses the existing SecretStore/AnalystSecrets abstraction. Credential identity binds provider ID, endpoint, kind/role, auth mode, profile partition, normalized custom-header names and a versioned MG01 credential-bundle boundary. Existing legacy plugin IDs do not erase an otherwise unchanged effective credential boundary. Blank fields retain prior values only at the same identity; endpoint/auth/profile/header-name changes cannot borrow the old values.
- API/header values exist only in trusted source/SecretStore memory during conversion. A validated credential bundle is written and read back before the public journal checkpoint is published. Write/read/format failures return fixed codes rather than credential-bearing store exception text. No credential values or raw source archive are put into SQL, manifest or checkpoint. Original settings are never written/deleted by this implementation.
- [SQLite journal](../../apps/agent-server/src/migration/mg01-journal.ts) stores public conversion and references under profile/migration ID. It requires the same closed-admission S36 backend epoch inside its transaction, rejects conflicting replays and validates stored counts/digests/schema on load. [Migration service](../../apps/agent-server/src/migration/mg01-settings.ts) rechecks source stability, epoch, public journal and credential readback. Every imported role stays `enabled: false`, `ready: false`; target controller failure remains `stop`, regardless of legacy fallback settings.

## Secret mode and recovery

The default is the actual in-memory **SessionSecrets** implementation. The public journal explicitly says `session-only`; restart/clear removes credential availability, and validation then fails. An explicit migration retry can recover from the still-owned fresh source after identity/epoch checks. A journal failure after secret transfer can be retried idempotently; it never authorizes source cleanup or enables a provider. Missing/invalid target secret bundles are not silently interpreted as plaintext legacy API keys.

A trusted OS SecretStore can be injected through the existing interface, but **no OS adapter or OS-store qualification was performed**. Undeclared plaintext modes are rejected. This code does not register an IPC/Chrome/Settings route, publish active settings or open admission. Source/target writers and SecretStore setup must respect the same migration fence in real composition. Partial secret-store writes and SQLite are separate durability boundaries; readback, immutable IDs and closed admission handle interruption without claiming cross-store atomicity. Source cleanup, credential lifecycle/retention and production rollback integration remain pending.
