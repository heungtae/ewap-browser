## 이번 수정

- 승인 이벤트에 지원 한도 4,096자의 전체 값을 전달한다. 앞·뒤 excerpt와 지문만으로
  가운데 변경을 숨기던 문제를 해결했다. 1,104자 가운데 변경과 최대 길이 Unicode의
  이벤트 계약 round-trip, 실제 긴 값 승인 카드 표시·DOM 입력을 검증한다.
- clarification 응답은 기존 AWAITING_VALUE run을 이어받는다. 새 run 생성으로 Panel의
  active-run gate가 새 승인 카드를 숨기던 Chrome 재현을 해결했다. run ID·tab·document·
  phase를 검사하며 이미 취소·종료되거나 다른 phase인 run은 재사용하지 않는다.
- 새로운 승인 카드가 표시되면 이전 value card를 잠그고 입력 내용을 제거한다.
- Chat Completions assistant tool_calls를 내부 `{id,name,arguments}`에서 wire 계약의
  `{id,type:"function",function:{name,arguments}}`으로 변환한다. tool_call_id를 보존하고
  입력 messages는 변경하지 않는다. Responses wire 계약은 기존 round-trip 테스트로 검증한다.
- 값 없는 동작 요청도 Act clarification에 도달하도록 LLM의 route·Act 지침을 보완했다.
  제품 코드에 요청 키워드·정규식·fixture ID 기반 값 추출이나 질문 결정 분기를 추가하지 않았다.
- 실제 ZIP에서 확인한 request text, conversation content, 승인값·excerpt, scalar 반환값,
  CDP 입력 text, SSE body·reasoning, UI detail의 원문 누출을 마스킹 경계에서 차단했다.
  길이·revision·판정·typed verifier 결과와 구조화된 context의 coverage는 유지한다.

## 재현 가능한 검증

`node scripts/chrome-s15-value-binding-smoke.mjs` 또는 `test:chrome-s15`를 사용한다.
`CHROME_FOR_TESTING_BIN`은 Chrome for Testing 실행 파일을 지정한다. 기본 모드는
통제 HTTPS Provider이며 실제 Side Panel의 승인·질문 폼·권한 UI와 실제 DOM을 사용한다.

- `search`: 명확한 값, value card 없이 승인 후 정확한 Search query 입력.
- `notes`: label을 Draft annotation, DOM ID를 memo로 바꾼 holdout, Unicode·따옴표 문구.
- `clarification`: 값 없는 요청, 모델 질문 도구, 응답을 같은 conversation/tool_call_id에
  반환, 새 제안 승인 후 정확한 입력.
- `long-value`: 1,110자 전체가 승인 카드에 나타나고 DOM 값과 일치.
- `multiple`: 서로 다른 두 필드·두 값에 승인 2회, DOM 대응 확인.
- `deny`: 사용자 권한 거부 시 입력 없음.

각 사례에서 실제 진단 ZIP을 생성하고 중앙 디렉터리·CRC·manifest SHA-256을 검사한다.
원본 입력값 부재를 검사하며 multiple은 두 값 모두 검사한다. 합성 테스트의 raw Provider
응답·DOM 값은 `/tmp` 실행 보고서에만 있고 이 저장소 증거에는 저장하지 않는다.

live 모드는 `S15_LIVE_MODEL`을 지정한다. 기존 `OPENROUTER_API_KEY`를 HTTPS proxy의
메모리에서만 사용하고 실제 제품 payload를 모델로 전달한다. proxy가 모델과 출력 한도
2,048 tokens를 설정하고 반환 message를 SSE로 전달한다. case ID·예상 tool·정답 값으로
모델 응답을 만들거나 수정하지 않는다. 지원 여부는 provider/model/build 조합별로 기록한다.
