## Chrome 권한 증거의 한계

Settings의 실제 클릭으로 `chrome.permissions.request()` 경로가 시작되는 것은 관측했다. Headless Chrome은 권한 팝업 결정을 자동으로 반환하지 않으므로, 승인을 받은 뒤의 전송은 통제 fixture의 Chrome profile Preferences에 해당 HTTP host pattern을 seed하고 Chrome을 재시작해 확인했다. 따라서 **권한 팝업에서 사람이 허용 버튼을 누르는 화면 동작은 검증하지 않았다.** 이 UI 팝업 승인 자체는 S4 로컬 자동 종료 조건에서 제외하고, 권한 전 차단·권한 후 전송·Settings의 사용자 gesture 요청 경로를 종료 조건으로 삼았다. 이는 운영 사이트나 실제 계정의 승인 증거가 아니다.
