# S29 authenticated read projections — 2026-11-02

Source base `e75ddf9fd` plus this change; the containing commit and [source hashes/machine evidence](s29-native-projection-2026-11-02.json) identify the verified sources. Linux, Node 20.19.6, pnpm 9.15.4, Chrome 147.0.7727.15, extension 0.1.117. S28/S29 remain **In Progress** pending their remaining acceptance. Original architecture/Sprint designs and the production entrypoint are unchanged.

The IndexedDB repository remains authoritative. A trusted browser caller may publish a transient, explicitly bounded read lease through `NativeBridge.publishProjection(read, admission)`. The caller supplies current source/task/document/runtime binding, cancellation and separate graph/sample/dataset permissions. The bridge binds it to the authenticated installation/profile and immutable graph revision/digest. UI messages cannot install these grants. The paired capability is enabled only by explicit `codebaseReadVersion: 1` configuration or an explicit trusted bridge option, and its request is included in the signed handshake. Legacy proof bytes and capabilities remain compatible.

The backend requests typed metadata search/inspection, an authorized immutable dataset, or a deterministic dataset query through `ProjectionChannel.read`. Closed request/reply schemas bind connection epoch, lease, source, document, operation digest, graph and data lineage, expiry and byte limits. Metadata omits samples and raw observations; samples and datasets require separate permission. No Node repository mirror, execution handle, model call or provider tool is introduced. Every read is fresh; the channel retains bounded pending/retired identifiers, not result data. Consumers must respect returned provenance/expiry and obtain a fresh authorized read for subsequent use.

Replies cross the existing integrity-checked transfer protocol in 128 KiB UTF-8 chunks with one outstanding ACK; maximum output is 8 MiB. Partial transfer cannot reach the bound projection consumer. Cancellation is sent in both directions; source leases are retracted and late results cannot resolve a cancelled read. Source/graph checks run before and after asynchronous reads/hash work and before transfer completion. Connection shutdown clears ephemeral authority. Caller revocation during a catalog await is fixed and tracked as [ISS-20261102-002](../issues/records/2026-11-02-codebase-read-freshness.md).

Actual Chrome loads the isolated target package, then composes source fixture callers in its real Worker. It uses the packaged content script, actual extension-origin IndexedDB, installed disposable native-host registration, packaged native relay and real authenticated Unix socket. The fixture daemon uses the same backend read channel with an on-offer consumer. It verifies collected Save metadata, inspection, a separately authorized 1,000-row synthetic Unicode dataset (620,567 transferred bytes), deterministic count and stale-document denial after real navigation. The collected graph reports partial coverage for the denied private region; input/private canaries are absent. The large dataset is generated transport evidence, not a claim of collecting 1,000 page rows. Admission is synthetic read-only admission. There are zero business dispatches, approval facts and provider calls.

Executed checks and exact commands are listed in the machine evidence. The focused tests cover signed capability downgrade/tampering, legacy compatibility, metadata minimization, paging, sample/data ACLs before reads, revoked scope, byte caps, digest-preserving semantic substitutions, wrong paired identities, reverse-frame replay, multi-frame Unicode transfer and bounded abort. Full native/management and panel regression runs retain their existing task-unavailable state.
