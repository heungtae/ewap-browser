권한·host·version 비교로 고쳤다. 필수 산출물, symlink, Claude 관련 파일,

## 실제 Chrome 검증

`scripts/chrome-s9-upgrade-smoke.mjs`가 깨끗한 임시 profile을 만들고
현재 `HEAD` archive에서 0.1.85를 별도로 build했다. 0.1.86 ZIP을 풀어
동일한 unpacked 경로에 복사한 후 같은 profile을 재시작하며
0.1.85 → 0.1.86 → 0.1.85 순으로 로드했다. 세 단계에서 확장 ID가
같았다. 첫 단계의 실제 Side Panel에서 통제 HTTPS Provider를 저장하고
Act 권한 질문을 거부했으며, 실제 Settings에서 skip mode를 확인 문구와
함께 저장했다. 후보 및 롤백 단계에서는 Provider 공개 설정, 저장된
권한 모드와 deny, 새 Panel badge가 복구됐다. 각 단계에서 새 Act를
시도해 저장된 deny가 페이지 변경을 차단하는 것을 확인했다. 실행 후
임시 Chrome profile과 fixture를 제거했다. 브라우저 제품 배포/스토어
설치 또는 운영 profile 업데이트를 뜻하지 않는다.

기존 transcript는 `chrome.storage.session`의 browser 수명 데이터다.
후보와 롤백 재시작 시 이전 transcript가 남지 않는 것을 실제 Chrome에서
확인했다. 이전 대화의 영속 이전은 이 후보의 동작이 아니다.
같은 schema v1의 Panel 재연결·worker 복구는 S5 및 확장 Chrome smoke로
확인했다. 실행 가능한 승인·권한 event는 복구 transcript에 남기지 않는다.

| 게이트 | 실제 결과 |
| --- | --- |
| TypeScript, ESLint, Prettier, module boundary, package policy | 모두 exit 0 |
| unit / fixture / source E2E | 95개 파일, 324개 테스트 통과 |
| S1~S8 Chrome | 8개 runner 모두 exit 0; Ask/Act, Provider, Settings, read/Vision, permission mode 회귀 |
| Chrome extension / preview | 두 runner 모두 exit 0; unpacked UI load, transcript 복구, preview/mutation |
| S9 Chrome upgrade/rollback | exit 0; 동일 profile·확장 ID, Provider/설정/deny 보존과 실제 거부 |
| release/package | exit 0; ZIP 두 번 생성 시 동일 SHA-256, package policy 통과 |
| source-size | 기존 대형 파일들로 exit 1. 신규 S9 script는 각각 200줄 미만 |

CDP attached-session 전체 시작·종료 횟수는 계측하지 않았다. S1/S2/S7/S8
runner는 각각 완료/Stop/오류 뒤 debugger detach를 검사했고 잔존
product-owned session을 발견하지 않았다. screenshot/video는 저장하지
않았다. fixture Provider에는 실제 credential을 사용하지 않았고,
검증 로그·패키지에는 provider secret, 원시 page content, screenshot,
action value를 기록하지 않았다. S1/S3/S7/S8의 음성 검사가 이 경계를
각각 확인했다. S9 로컬 범위의 미해결 critical/high blocker는 없다.
