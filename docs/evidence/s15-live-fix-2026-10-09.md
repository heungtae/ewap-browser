## 원인과 수정

- 스트리밍 parser가 `finish_reason:length`를 버려 잘린 인자가 일반 JSON 오류가 됐다.
  Chat Completions와 Responses의 출력 한도 종료를 보존한다. 잘린 응답·invalid JSON은
  실행하지 않고 실제 call ID의 오류를 같은 대화에 돌려주며 한 번만 재요청한다.
  모델이 여러 mutation 제안을 묶어 보내도 어떤 호출도 선택·실행하지 않고 계획 검토를
  먼저 요청한다. 두 번째 오류와 cancellation은 종료한다.
- 긴 반복 문자열은 output budget을 늘리거나 재요청만 해도 재입력을 요구했다.
  256 UTF-16 code units보다 긴 원래 요청에 turn-local opaque source ID와 경계 문자
  근거를 제공한다. 모델이 `value_span: {source_id, start, end}`를 선택하면 core가
  해당 substring만 복원한다. 업무 키워드·정규식으로 값이나 질문 여부를 판단하지 않는다.
  ID/revision·정수 범위·Unicode 경계·4096자 제한을 검사하며 literal과 span의 동시
  제출 및 이전 turn의 ID를 거부한다. 기존 parser·민감값 차단·계획 결속·전체 값 승인·
  dispatch/DOM verifier를 유지한다. 원문·경계 배열과 helper callback은 trace에서 마스킹한다.
- 기존 질문 사례의 실제 terminal은 `INCOMPLETE / GOAL_UNMET`였다. action 1개는 VERIFIED,
  observation은 current였지만 모델이 검색 전체 목표를 incomplete로 보고했다.
  이를 내부 오류로 표시하던 경로에 `GOAL_INCOMPLETE`와 남은 작업 안내를 추가했다.
  typed 결과나 원래 목표를 바꾸지 않으며 검증된 동작을 자동 반복하지 않는다.

`strict:true`만으로 출력 한도 중단을 해결할 수 없으므로 이번 변경은 provider별 strict
지원에 의존하지 않는다. JSON을 core가 복구하거나 입력값을 짧게 바꾸지 않는다.
