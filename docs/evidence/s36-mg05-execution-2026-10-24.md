## Source and implemented behavior

- [Legacy request decoder](../../apps/chrome-extension/src/migration/mg05-request.ts) accepts the actual persisted request fields and shared stage/completion/error contracts. Migration has no restore TTL or silent last-100 slicing: old terminal summaries remain accounted for. The decoder is migration-specific; stricter safe integer/tab constraints quarantine unsupported records. Containers over 100 requests are quarantined as a whole and remain in the local backup.
- [Converter](../../apps/chrome-extension/src/migration/mg05-convert.ts) archives `execution_requests_v1` and makes discard markers for `contextpilot_pending_workflow_selections_v1`. It preserves historical terminal outcome/completion separately from drain requirements and dispatch uncertainty. Running rows stay marked as requiring drain; conversion itself does not terminate them. Records are explicitly non-executable and non-resumable. Old owner/document authority is absent from the target projection. Invalid/duplicate requests are indexed quarantine entries, never silently filtered.
- Pending selections are never deserialized into executable candidates. Their complete original payload stays in the browser-local recovery snapshot; target markers contain only source digest/index and `authorityImported: false`. No selection ID, prompt, candidate, value or approval is promoted into target authority. The container is limited to eight selections; individual payload shapes are deliberately discarded rather than interpreted.
- [Drain orchestration](../../apps/chrome-extension/src/migration/mg05-drain.ts) checks a trusted frozen epoch, cancels active requests through a port, rereads identity/revision-bound observations, revokes selections, checks remaining live work independently of the persisted list, and reconciles owned CDP cleanup. It preserves earlier dispatch hints even if later cancellation metadata omits them. Any active work, remaining selection authority, unknown dispatch or unresolved CDP blocks `ready`. Hung operations time out and abort the signal; no automatic dispatch/replay/retry or admission-open operation exists.
- [Lifecycle adapter](../../apps/chrome-extension/src/migration/mg05-lifecycle.ts) calls the existing `status`, cancellation callback, `endTab` and `flush`. It does not create a second executor. The actual lifecycle turns cancellation after dispatch into UNKNOWN and invalidates the old RequestContext. Cleanup must use the injected owner-aware CDP path, never an unconditional detach.
- [MG05 staging](../../apps/chrome-extension/src/migration/mg05-staging.ts) reuses the atomic profile-specific IndexedDB staging implementation with its own namespace/schema and both session storage keys. Originals and checkpoint are local; snapshots are not sent to providers/backends or printed. Staging preserves the post-drain source; explicit cancellation/flush intentionally changes legacy request state before that snapshot is taken.

## Readiness boundary

The adapter is implemented and exercised against the actual legacy lifecycle in controlled tests, but **is not registered in the production Worker**. Production admission/writer fencing, full live inventory, selection authority revocation and owned CDP reconciliation remain trusted integration ports. `remainingActive` must cover all runtime-owned tasks, not just the persisted request list; returning source-list length is insufficient. Every port must honor epoch/cancellation and complete before reporting counts. Timeout leaves readiness unestablished even if late cleanup later settles.

`ready` is a bounded reconciliation result, not S36 release qualification or a cutover grant. An absent live row for an active stored request remains unresolved. Old terminal UNKNOWN stays a blocker without fresh matching reconciliation. A verified historical action does not turn an unknown goal into completion. Staging can retain inspection-only records while readiness is false; it does not acknowledge or activate migration. Full coordinator composition and release acceptance remain pending.
