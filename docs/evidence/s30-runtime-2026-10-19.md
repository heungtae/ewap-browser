## Delivered implementation

- `tool-registry`: 21 strict intent schemas, canonical/wire bijection, versioned
  prepared/receipt/approval contracts, current capability snapshots and explicit
  executor/verifier requirements. S32/S33/S34-owned operations cannot register yet.
  Inventory presence alone never advertises a tool. Twenty-one tool schema and
  five runtime/approval schema goldens pin the current target contract.
- `tool-runtime`: runtime-issued invocation IDs, current document/owner/mode/plan/
  policy/capability/argument/predicate bindings; scoped trusted UI argument refs;
  zero-command no-op; injected backend intent port before browser reservation;
  one-use approval immediately before dispatch; bounded execution with late
  callback rejection; independent postcondition results and `goalVerified:false`.
  Partial/missing dispatch evidence remains unknown and is never automatically
  redispatched. Stop revokes approvals and closes that runtime instance.
- `policy-engine`: deny priority; Ask mutation and sensitive-input rejection;
  exact prompt/plan/context/effect/source-scope binding; Full retains explicit
  approval for unknown autosave, destructive/bulk/external-transfer effects.
  UI authority uses private identity proofs; runtime message metadata must match
  an exact current Side Panel context. Models cannot supply approval receipts.
- `browser-runtime`: ephemeral unique current bindings; visible/enabled/unoccluded
  native text, single-select and checked-control adapters; reviewed typed
  navigation/tab/business-action ports and a bounded current-focused CDP text
  port. These ports require trusted independently observed adapters; arbitrary
  model JavaScript, command names, functions and API replay have no executor.
  Unsupported file/range/date/number/password/multiple/contenteditable paths
  stay unavailable rather than claiming old capability-parity coverage.
- Real IndexedDB `dispatchLedger` reservation/settlement transactions use S29's
  existing database. Same dispatch/different digest conflicts; duplicate settled
  dispatch returns its receipt; duplicate unsettled dispatch remains unknown.
  No argument value or page body is written to that ledger. S31 still owns the
  durable backend intent implementation and process-recovery qualification.
- Target app composition exposes actual mutation handlers through the shared
  continuation and projects prompts into preserved `event-card`, heading, detail
  and action markup. Prompts show the exact admitted value using textContent.
  Responses are pinned to their original toolCallId and prompt/plan revisions.
