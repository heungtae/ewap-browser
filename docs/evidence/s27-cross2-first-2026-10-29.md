# S27 cross-case independent evaluation — first run, 2026-10-29

The [first live report](s27-cross2-first-2026-10-29.json) records **288/288
matching observations, 12/12 complete case groups and 288 HTTP 200 responses**
from native `jev-1.13.0`. The separately authored [corpus](../baselines/s27-cross2/corpus.json)
was fixed before this run; its author was instructed not to read the repository
or previous outcomes. Its 12 synthetic requests cover four reads, four explicit
search-form actions and four evidence-based analyses, in English and Korean.

Each request was evaluated over eight decision phases. Candidate order was
reversed independently; intent was additionally tested in both Ask and Act
modes. Evidence completeness and safe-recovery availability were crossed with
candidate order in their respective phases. The 288 observations comprised 152
Ask and 136 Act frames. Eight selected search fragments bound the exact user
identifier; eight selected analysis fragments bound the acquired-dataset source.
Each also rejected a different individually valid source with
`ARGUMENT_SOURCE_CHANGED`. This validates source binding in the fixture, not
fresh DOM-target binding, user consent or real execution.

An independent review of the previous [cross-case attempt](s27-cross-first-2026-10-29.md)
found seven analysis next-step expectations under-specified. The previous result
and its inputs remain unchanged. Before this new corpus was authored or called,
the fixture was changed to specify the acquired evidence package and its scope,
exclude an unauthorized later page revision, and bind the dataset used by the
selected analysis fragment. The independently authored new requests were not
used to tune the questions after this run.

The report retains the synthetic frames, request digests, bounded parsed
native response bodies, local validated results, HTTP statuses and counters.
The checker reconstructs each request and candidate binding, reparses the saved
native answer, and checks the selection and source-change negative. Frame and
request correlation is attached locally by the adapter; no provider-signed
echo is claimed. Corpus, runner, fixture, observation, vocabulary, schedule,
negative-check and bundled protocol hashes are checked. No credential or real
page content is stored.

These are independently constructed synthetic **phase observations**, each
with a fresh context and budget. They do not establish sequential task
continuity, browser dispatch, a real user goal, MCP or release qualification.
The retained [first-run source snapshots](../baselines/s27-cross2/) match the
recorded source hashes. Run the current checker against the saved report with
`node scripts/s27/check-multiphase.mjs docs/evidence/s27-cross2-first-2026-10-29.json`.

The run used Node `v20.19.6`, pnpm `9.15.4`, Linux x86_64 and source base
`764ac9e88e9d5912b74ab99ae0f086330cf5bfa8` with uncommitted controller and
evaluation changes. The first live call used
`S27_MULTIPHASE_REPORT=/tmp/s27-cross2-first-20261029.json node scripts/s27/live-multiphase.mjs`
inside the interactive credential environment. No browser dispatch or approval
was performed.
